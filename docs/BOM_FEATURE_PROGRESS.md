# 图纸 BOM 自动构建：本轮开发汇报

## 一、本轮交付

本轮围绕两件事展开：**让企业能自行定义 BOM 的输出字段**，以及**让用户决定多页图纸合成一份 BOM，还是按页独立输出**。两部分都已接入 Web 界面。

| 改动 | 已交付内容 |
| --- | --- |
| 标题栏与明细栏统一配置 | 原来的企业字段和标题栏 JSON 模板合并为「企业 BOM 输出模板」，统一使用「输出名称＋取值来源」配置。标题栏是每张图一份，零件明细是每个零件一行。图纸材料和零件材料分别读取；标题栏提供 7 个常用字段及设计、校核／审核、批准预设。 |
| 企业自定义字段 | 可用系统预设，也可按原图标签读取标题栏独有字段、按列名逐行读取明细自定义列。标题栏支持备用来源；零件明细可引用同一来源页的标题栏值，也可配置固定值或留空。未读到的数据不猜填。 |
| 模板保存、示例和校验 | 支持统一保存、重启后继续使用、导入、下载和预览，兼容旧版企业字段和标题栏文件。示例包含默认字段与自定义示范。保存或下载时会自动定位并标红未填或重复的字段；切换页签不再改变下载内容。 |
| 多页文件的两种输出方式 | 共用逐页识别。合并时按原页顺序汇总，不重编序号、不自动去重、不改原数量；同件号跨页出现会提示复核。逐页独立时，每页展示自己的标题栏、明细、数量合计和基本校验，可单独下载 JSON、CSV、Excel（含企业版）。 |
| 多页识别状态与来源追溯 | 逐页显示识别行数、未提取到明细、疑似漏读或失败。失败不计为零行；存在失败或疑似漏读时暂停合并导出，逐页模式的成功页仍可导出。修复裁切回退页码错误和跨文件版面缓存串用问题。不同图号时不自动选主标题栏，企业导出中引用的标题栏字段按每行来源页取值。 |
| 设置页整理 | 暂时移除「企业关联索引」配置区及其跳转入口；后台接口、已有数据和版本对比功能保留。审图规则、参数词典与 BOM 输出模板分开。 |

## 二、当前边界与建议优先项

| 项目 | 当前状态／下一步 |
| --- | --- |
| BOM 树 | 合并模式已接入现有装配候选树生成流程，但当前演示配置关闭了装配推理。标准 JSON／Excel 可携带已生成的树；逐页独立树、不同图号装配与子总成的自动挂接、企业版树结构导出均未做。 |
| 复杂续表 | 当前支持按页汇总完整明细行。无表头续页的表头继承、跨页半行拼接、重复印刷的自动消重还没做；本轮逐页结果仅支持查看和导出，不支持单页编辑保存。 |
| 原图与 BOM 一致性 | 已有数量缺失或非正数、件号重复、球标与明细序号差异和人工复核提示。装配展开量对账是现有能力，需有可用的树；不等同于独立复读原图并逐行核对最终 BOM。建议下一步先做「原图数量独立复读＋差异清单」，再补可配置的企业物料编码校验。 |
| 甲方验收 | 已跑通本地流程，尚未用甲方标注图纸验证识别准确率或检出率，也未用甲方 ERP／PLM 的实际模板做试导入。球标差异属于待核实的候选，不等于图纸漏标或 BOM 漏行。 |

## 三、验证与演示

- 本地开发工作区 569 项 Python 回归测试通过；仅含本轮提交内容的干净副本中，563 项 Python 回归测试和 5 个前端测试脚本通过。
- 用同一份双页 PDF 验证了合并得到一份 BOM、逐页可分别导出，并核对两种方式的明细行一致。另用测试样例验证失败页不计为零、不会拦住逐页模式的成功页。
- 建议汇报时先用甲方样表配置「物料编码」「自定义明细列」「所属图纸图号」三列，再对同一份多页样例分别演示两种输出方式。离线演示只验证流程和格式，识别精度应另用真实模型和原图验收。
